# Project Scope

## Project Name

ProofRoom

## One-Line Summary

ProofRoom is an agent-native B2B evaluation room where a buyer and their browser agent evaluate product fit against structured evidence, visible assumptions, and human-approved decision state.

## Target User

The primary user is a B2B software buyer using an AI browser agent to evaluate a vendor. The canonical buyer is a member of a fintech buying committee who must align marketing, finance, security, and operations requirements without trusting unsupported marketing claims.

## Problem

B2B sites are built for people to browse and agents to scrape. Product claims, security facts, integrations, pricing assumptions, and customer proof appear across disconnected pages and documents. The buyer and agent lack one shared place to evaluate requirements, expose gaps, edit assumptions, and preserve a decision trail.

## Product Thesis

The next generation of B2B sites should expose structured evidence and decision workflows to the agents helping people buy. WebMCP makes that possible in the live page without adding a second chatbot or moving the user into a separate automation system.

## Core Workflow

1. A buyer opens Northstar, a fictional campaign operations product site.
2. The buyer asks their browser agent to evaluate Northstar for Meridian Bank.
3. The agent reads the room and stages the buyer context.
4. The person reviews and approves exactly what context becomes authoritative.
5. The agent searches twelve evidence records, stages six requirements, attaches evidence, and evaluates coverage.
6. The system keeps EU data residency `unknown` because the evidence catalog cannot prove it.
7. The agent calculates ROI from visible assumptions and saves CFO and CISO briefs.
8. The person changes the budget ceiling and marks EU residency non-negotiable.
9. The agent proposes a `not ready` decision.
10. The person inspects the evidence and activity receipt before approving the decision.

## What We Are Building

- A premium fictional B2B product page that works without an agent
- A visible approved buyer-context panel
- A requirement and evidence workspace for six fixed requirements
- A deterministic ROI calculator
- CFO and CISO decision briefs
- A decision proposal with human-only approval
- A real activity ledger generated by shared domain actions
- Nine imperative WebMCP tools
- A WebMCP unsupported and registration-error fallback
- Browser-local persistence and deterministic reset
- Automated domain, component, tool, accessibility, responsive, and end-to-end tests
- A versioned eval manifest and runner
- Cloudflare deployment with required headers
- Public open-source documentation and release evidence

## What We Are Not Building

- Real vendor, buyer, or customer data
- User accounts or authentication
- Neon or another database
- Application-side AI chat or model calls
- CRM or outbound email integrations
- Arbitrary URL, PDF, or evidence ingestion
- Multiple vendor comparison
- Real-time team collaboration
- Procurement, contract, or payment execution
- A generalized SaaS evaluation platform
- A mobile editing experience; mobile remains readable and navigable

## Aesthetic Direction

ProofRoom should feel like an editorial due-diligence desk inside a premium software site.

- Warm paper surface
- Deep ink product panels
- Acid green verified-evidence accents
- Cobalt agent-work accents
- Rust gaps and contradictions
- Editorial display type paired with precise sans-serif UI and mono evidence metadata
- Asymmetrical compositions and evidence stamps
- One orchestrated transformation after buyer-context approval
- No purple gradient, glass dashboard, generic card wall, or eyebrow-headline-dek stack

## Inspiration And References

- High-trust financial research terminals, for structured evidence and state
- Editorial product storytelling, for a readable premium first impression
- Code review systems, for visible proposals, diffs, and approval integrity
- Browser developer tools, for an honest activity ledger
- The official WebMCP React examples, for native tool registration and shared actions

## Time Budget

Autonomous build and audit until the acceptance checklist passes. Target release candidate by September 2, 2026. Keep September 3 as submission buffer only.

## Demo Path

The demo begins on the unpersonalized product page, runs one buyer-evaluation prompt, shows context approval, evidence-backed requirement evaluation, one deliberate unknown, an ROI adjustment, CFO and CISO briefs, a `not ready` proposal, and the real activity ledger. The entire story must fit comfortably inside a three-minute video.

## Submission Story

Most B2B websites make buyer agents scrape marketing claims. ProofRoom exposes structured evidence and a shared evaluation workflow. The person keeps control of context and decisions; the agent performs structured research and staging; the page shows exactly what changed and why.

## Success Signal

A judge can open the public URL, reset the room, complete the canonical agent journey in a supported browser, complete the same journey through normal UI controls, inspect every conclusion, and reproduce the project from the public repository.
